# Документация по нормализации данных доставок

## Исходные данные
- Файл: deliveries.parquet
- Количество строк: 9,461,993
- Количество колонок: 25

## Нормализация до 3НФ

### Проблемы денормализованной таблицы:
1. **Избыточность данных**: 
   - user_phone повторяется для каждого заказа пользователя
   - store_address повторяется для каждого заказа из магазина
   - item_title и item_category повторяются для каждого заказа товара

2. **Аномалии обновления**:
   - Изменение номера телефона требует обновления всех связанных заказов
   - Изменение адреса магазина требует обновления всех заказов из этого магазина

3. **Аномалии вставки**:
   - Невозможно добавить товар без привязки к заказу
   - Невозможно добавить курьера без привязки к доставке

4. **Сложные зависимости**:
   - item_replaced_id требует обработки замен товаров
   - Смены курьеров требуют отдельной логики обработки

## Нормализованная схема (3НФ)

### 1. Таблица users (Пользователи)
- **Нормализация**: Выделение сущности "Пользователь"
- **Обоснование**: user_phone зависит от user_id, а не от order_id

### 2. Таблица stores (Магазины)

- **Нормализация**: Выделение сущности "Магазин"
- **Обоснование**: store_address зависит от store_id

### 3. Таблица items (Товары)
- **Нормализация**: Выделение сущности "Товар"
- **Обоснование**: item_title и item_category зависят от item_id

### 4. Таблица drivers (Курьеры)
- **Нормализация**: Выделение сущности "Курьер"
- **Обоснование**: driver_phone зависит от driver_id

### 5. Таблица orders (Заказы)
- **Нормализация**: Основная сущность "Заказ" с внешними ключами
- **Обоснование**: Центральная таблица с метаданными заказа

### 6. Таблица order_items (Позиции заказов)
- **Нормализация**: Разрешение связи many-to-many между orders и items
- **Обоснование**: Один заказ может содержать несколько товаров

### 7. Таблица delivery_history (История доставки)
- **Нормализация**: Обработка смен курьеров во время доставки
- **Обоснование**: Один заказ может иметь несколько курьеров

## Преимущества нормализованной схемы

1. **Устранение избыточности**: Данные хранятся один раз
2. **Целостность данных**: Внешние ключи обеспечивают согласованность
3. **Гибкость**: Легко добавлять новые сущности
4. **Производительность**: Индексы оптимизируют запросы
5. **Поддержка**: Упрощенное обновление данных

## Витрины данных

### 1. Витрина orders_daily
- Агрегация по дням, городам и магазинам
- Содержит основные метрики по заказам
- Оптимизирована для аналитических запросов

### 2. Витрина product_sales_daily
- Агрегация по товарам, категориям, дням
- Содержит метрики по продажам товаров
- Включает ранги популярности
